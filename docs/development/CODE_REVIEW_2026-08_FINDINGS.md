## Area R3 — AI credentials + secret storage

This area holds and retrieves vendor API keys: the OS credential stores (`MacOsKeychain` via SecItem P/Invoke, `WindowsDpapiStore` via ProtectedData over per-provider files), the routing layer (`AiCredentialStore`), the two-source environment reader (`AiEnvironmentKeys` merging process env with the login-shell snapshot), the shell probe itself (`ShellEnvironment` + `ProcessShellProbeRunner` + `ShellEnvParser`), and the opt-in gate (`AiEnvironmentCredential`, `AiCredentialMethod`). I read every file at HEAD, traced the DI wiring and both UI subscribers in `App.axaml.cs` / `AiConnectionsViewModel` / `SettingsViewModel`, and checked the five test files covering this area. Overall health is high: no path logs, persists, or passes a secret value anywhere it should not, the no-silent-adoption rule holds end to end, and the generation counter does its job. The real defects are an event raised a moment too early, and two places where distinct failure states collapse into one.

I read all twelve files in full, traced the cancellation/supersede paths, the error taxonomy end to end, and the two adapters against each other, and checked the test suite (which is unusually thorough — exhaustive think-tag chunkings, a split-diacritics read-boundary test, cancellation-semantics tests on both providers). Overall this is careful, well-tested code with no retry loops, bounded error-body reads, and genuinely good credential hygiene; what I found is one real state bug in reachability reporting, one already-tracked resolver bug still present at HEAD, and a handful of narrow robustness gaps.
